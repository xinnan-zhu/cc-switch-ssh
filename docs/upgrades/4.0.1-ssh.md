# CC Switch SSH 升级到 4.0.1

## 结论

采用保留历史的合并，并按官方新架构适配 SSH 功能。无需从最新版重新逐个搬运旧提交。

- 原分支：`ssh-remote-provider-next`，提交 `344c169f`（`v3.20.4-ssh.3`）。
- 官方基线：`upstream/main`，提交 `4804b723`，应用版本 `4.0.1`。
- 升级分支：`codex/upgrade-4.0.1-ssh`。
- 官方新增 169 个提交，净改动涉及 591 个文件。合并预演只有四个内容冲突文件：`App.tsx`、`handler_context.rs`、`forwarder.rs`、`services/proxy.rs`。

原分支已合入过官方的部分配置和模式重构。SSH 自定义功能主要集中在独立模块，因此继续合并能保留远程配置、隧道、数据库兼容修复和 fork 更新渠道，并保留后续更新所需的共同历史。

## 适配结果

- SSH 配置入口接入新版应用页头及导航模型，仍支持 Claude Code、Codex、Gemini CLI。切换到不支持的应用时返回供应商页。
- 页头保留远端网关主机状态，点击管理可以跳转到指定主机。
- 网关配置调用新版 Claude / Codex 写入接口，保留远端设置、登录和 Codex 自有供应商 ID。
- 固定供应商的远端只请求该供应商，并禁用本地故障转移。聚合模型不能绕过固定路由；跟随本地的远端允许已发布的聚合模型，但仍拒绝依赖本机官方登录的供应商。
- 远端 Codex 普通路由在供应商变化后刷新上游模型；聚合请求保留已解析的具体模型。
- 本地退出路由时，只要远端路由仍启用，共享代理服务就继续运行。显式关闭整个代理或退出应用仍会停止服务。
- 远端请求保留按主机记录的用量来源，在新版详情和速度统计里按代理请求处理。
- 云同步不导出 SSH 主机和网关令牌，并保留本机网关表；从官方数据库同步也不会清除本机隧道配置。完整备份仍包含这些表。
- Fork 的更新地址和签名公钥保留，发布工作流采用仓库固定的 Rust 工具链。

## 验证

- 前端全量：184 个测试文件、2150 项测试通过。首次高并发运行出现一项上游测试竞争，单独复跑及降低并发的全量复跑均通过。
- 前端类型检查、格式检查及生产构建通过。
- Rust Clippy（所有 targets，警告视为错误）通过。
- 供应商服务、供应商命令、代理命令、导入导出四组后端集成测试：82 项通过。
- 后端全量：3356 项通过，10 项按仓库设置跳过。
- 浏览器预览检查了 SSH 页在新版侧栏和页头中的布局。浏览器没有 Tauri 后端，预览使用空状态。

新增回归覆盖固定远端路由、聚合模式与官方登录限制、本地退出路由保留远端服务、云同步保留网关令牌，以及远端请求的用量展示和速度口径。

本机正在运行的服务占用了上游一项测试的固定端口。该测试改用临时端口，验证实际绑定地址并显式关闭测试服务；未更改产品的默认监听端口。

## 交付范围

本地验证完成后，发布版本使用 `v4.0.1-ssh.1`，由 fork 的发布流水线生成各平台安装包与自动更新文件。没有安装覆盖本机现有应用。真实 SSH 服务器反向隧道联调测试仍按原仓库设置跳过。

数据库 schema 仍为 19。若要试用新版并准备回退，应先备份 `~/.cc-switch/` 以及相关客户端配置；仅切回 Git 分支不能撤销应用运行后对客户端文件和设备状态的改动。官方具体回退步骤见 `docs/release-notes/v4.0.0-zh.md`。
