## 实现

- 超时根因：tokio `ChildStdin::shutdown()` 在 Unix 上是空操作，不关闭管道。`python3 -` 等不到 EOF，每次都触发 75 秒超时。改为写完后 `drop(stdin)`。`collectors_finish_once_stdin_is_sent` 用本地 shell 替代 SSH 驱动同一段管道逻辑，旧写法下该测试复现超时。
- `run_collector` 先跑 `python3 -`；退出码 127 时改跑 `sh -c '<REMOTE_PATH_PRELUDE>exec node -'`，复用远端 CLI 检测的登录 shell PATH。都缺失时报「远端需要 Python 3 或 Node.js」。
- `remote_usage_collector.cjs`：Python 采集器的逐行移植，游标 key、事件 ID（Python `json.dumps(sort_keys)` 格式的 sha256）、断点结构一致。纳秒 mtime 和 inode 超出 JS 安全整数，配置用 `parseConfig` 解析、输出时原样写回，避免精度丢失导致断点失配。`.cjs` 后缀避免被仓库的 `"type": "module"` 当作 ES 模块。
- 采集器测试复用同一套用例跑 Node 版，另加 Python／Node 输出一致性对比。CI 有 node 时自动覆盖。
- 前端：`RemoteProviderPage` 用 `PageTabs` 分为 providers／host；`App.tsx` 远端视图使用 `AppPageHeader` 的 `leading` 返回按钮。
