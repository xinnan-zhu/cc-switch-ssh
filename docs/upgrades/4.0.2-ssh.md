# CC Switch SSH 升级到 4.0.2

## 合并范围

合入官方发布标签 `v4.0.2`（`bf2fe0d0`），保留 SSH 功能和共同历史。相对上一版官方基线 `4804b723`，新增 17 个提交、102 个文件，自动合并没有内容冲突。升级分支为 `codex/upgrade-4.0.2-ssh`。

官方 4.0.2 仍标记为预览版，但已修复影响实际使用的 ChatGPT 账号对话 400、Codex 模型目录和 Claude 聚合模型选择问题，值得作为当前 4.0.1 fork 的下一次升级。

检查时官方 `main` 为 `3af74823`。标签之后的 4 个提交涉及 Claude 自动模式字段、MCP/提示词全页编辑、MiMo 预设和 OpenCode 原生 v2 配置，留待后续版本合并。

## SSH 兼容性

- 继续通过官方 Claude / Codex 配置补丁写入远端，保留远端登录、Codex 路由 ID、MCP 和用户设置。
- 回归验证 Claude 远端切换会清除过期的 `modelPicker`，防止继续显示上一套聚合模型。
- 回归验证 Codex 远端模型目录会替换其他工具的旧指针；没有模型目录时清除指针，同时保留远端登录和路由 ID。
- 固定远端供应商、跟随本地聚合路由、本地退出路由后保留共享代理，以及云同步保留设备网关记录的既有测试继续运行。
- 更新摘要按官方版本匹配 `-ssh.N` 构建，首次更新能显示当前摘要，同一官方版本的后续 SSH 构建不重复显示该摘要。
- Fork 的更新地址和签名公钥保持有效。

## 发布流程

SSH 标签只触发 fork 发布工作流。三平台构建完成后，由 Actions 的 `needs: release` 自动启动发布步骤，生成更新清单并读取对应的 `docs/release-notes/<tag>-zh.md`；没有专门说明文件时使用原来的通用说明。

不以轮询 GitHub 构建状态推动后续步骤。目前没有 GitHub webhook 直接唤醒当前聊天的通道；发布所需的后处理由工作流自行完成。

## 升级限制

官方数据库 schema 从 19 升到 20。第一次打开新版前应保留备份；新版会自动创建迁移前数据库备份。回退旧版需要恢复对应数据库备份，仅切换代码分支无法降级数据库。

Claude 聚合模型选择要求远端或本机 Claude Code 2.1.243 及以上。真实 SSH 服务器反向隧道联调仍未运行。此次合并不安装覆盖本机应用，也不创建新的发布标签。
