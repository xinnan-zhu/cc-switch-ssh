## Gateway model selection

Native Codex Responses requests previously ran an extra gateway-only model substitution: if the selected model was absent from the provider's saved catalog, the proxy replaced it with that provider's default model. For example, selecting `gpt-6.1-sol` could send `gpt-5.6-terra` upstream. Native Responses forwarding now honors the request's model, matching local forwarding. Explicit provider changes still push the provider configuration to the remote host; Chat/Anthropic conversion retains its existing model mapping.

The regression test exercises the real request router with a recording upstream, covering pinned and following routes, with and without a provider catalog, and both `/responses` and `/responses/compact`.

## Database and usage compatibility

The SSH branch and upstream assigned different migrations to database version 21. Version 24 reconciles both layouts after upstream migrations: it repairs the Agy flags skipped by SSH v21 and adds the usage source dimension for upstream databases. Existing rollups retain their counts and costs; existing remote source labels remain unchanged. Tests cover upstream versions 20–23 and SSH version 21, repeat migration, and insertion of identical usage dimensions for another host.

The upstream usage dashboard now loads model options lazily and queries tab counts separately. Pass the selected host to those queries as well as the existing charts and tables so remote usage filters remain consistent.
