## 网关修复

- **按应用授权（P1）**：`remote_route` 返回跟随本地、固定供应商、拒绝三种结果。只有 `enabled=1` 的路由可以访问，`provider_id` 为 NULL 才表示跟随本地。网关监听器在 token 校验后按请求路径确定应用（Claude、Codex、Gemini、Grok Build），路由未授权返回 403，其余路径返回 404。`RequestContext` 和 Stack 校验对拒绝的路由同样报错，不会退回本机路由。
- **共享端口迁移（P2）**：端口改为主机级操作。`enable` 发现端口变化时，会一起推送该主机所有已启用应用，并锁住这些应用防止并发切换。隧道失败或任一应用推送失败时，已推送的应用改回旧端口，数据库端口和隧道一并恢复。
- **Gemini 模型（P2）**：远端 Gemini 请求经过转发器时，把 `/models/<model>` 改写为路由供应商的 `GEMINI_MODEL`（或 `model.name`），出站模型也按改写后的值记录。
- **TOML 预览（P2）**：遮罩逻辑提取到 `src/utils/remoteConfigPreview.ts`，同时覆盖 Codex 和 Grok Build，取代 4.0.4-ssh.1 中页面内联的 Grok TOML 遮罩。
- **Grok Build**：检查后确认 Grok 存在同样的授权问题，原因是网关只识别 Claude、Codex、Gemini 的路径。`/grokbuild/v1/responses[/compact]` 现在映射到 `grokbuild` 路由。端口迁移和预览遮罩自动覆盖 Grok。Grok 使用稳定的客户端模型配置，由代理改写为上游模型，不存在 Gemini 那样的模型问题。

## 官方合并

唯一的冲突在 `forwarder.rs::forward` 开头：官方新增 `codex_upstream_format_out` 初始化，本分支新增 Gemini 模型改写，两段都保留。官方新增 GitHub Copilot 托管账号（Codex），其凭据由本机代理注入，和 xAI OAuth 一样可以通过网关使用，不需要额外限制。

## 发布流程

源码版本号仍为官方 `4.0.4`。推送 `v4.0.4-ssh.2` 后，`release-fork.yml` 生成完整版本号 `4.0.4-ssh.2`，Windows MSI 使用 `4.0.4.2`，三平台构建成功后自动发布并核验资产。

## 验证结果

- 前端全量：198 个文件、2318 项测试通过；tsc、Prettier、vite 生产构建通过。
- 完整 Rust 测试集：3664 项通过、10 项按仓库设置跳过，单线程，`CC_SWITCH_TEST_HOME` 指向临时目录；`cargo clippy --all-targets` 无警告。
- 新增回归测试：共享隧道上禁用、未启用、固定供应商失效的应用被拒绝（真实本地监听器）；Gemini 在两个不同模型供应商之间切换时的出站 URL；两应用端口迁移及中途失败回滚；Codex/Grok TOML 凭据遮罩。
- 未实测：真实 SSH 主机上的端口迁移、原生 Windows SSH/ASKPASS。
