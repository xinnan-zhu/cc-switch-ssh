# CC Switch SSH 4.0.8-ssh.1

- 已发布版本：`v4.0.5-ssh.1` / `68cc7e2d`。
- 本次合入官方稳定标签 `v4.0.8` / `df40d53c`（相对上次合入的 `2db86e94`，增加 56 个提交，含 4.0.6、4.0.7、4.0.8）。
- 分支：`codex/upgrade-4.0.8-ssh`；发布标签：`v4.0.8-ssh.1`。
- 合并仅 `src/App.tsx` 一处冲突：官方在页头新增搜索按钮的 `Search` 图标与 fork 远端按钮的 `Server` 图标同处一个 import，保留两者。页头按钮顺序为网关指示、远端、配置切换、搜索、添加供应商，互不遮挡。
- fork 的更新地址、公钥及 `release.yml` 对 `v*-ssh.*` 标签的排除保持不变。官方 `release.yml` 新增的 deb/rpm 缺失即失败只作用于官方流程；fork 的 `release-fork.yml` 已要求 deb/rpm 及其签名，无需改动。

## 远端 CLI 一键更新

- 后端 `services/provider/remote_cli.rs`：一次 SSH 调用检测 Claude Code、Codex、Gemini CLI、Grok Build 的路径、解析后的真实路径和 `--version`；最新版本在本机复用官方「应用」页的 npm dist-tags 查询（`npm_latest_version_for_tool`）。
- 安装方式按真实路径判断：`node_modules/<包名>/` 为 npm（优先于 Homebrew，避免 brew 的 node 下的 npm 全局包被误判），`Cellar`/`Caskroom` 为 Homebrew，`~/.local/share/claude/`、`~/.grok/bin|downloads/` 为官方安装。无法识别的 Codex、Gemini、Grok 不提供更新；Claude Code 退回其自带 `claude update`。
- 更新命令：npm 使用二进制同目录的 npm，不存在时用 PATH 上的 npm，参数复用官方 `npm_install_extra_args`（Claude Code 的 npm 12 安装脚本参数）；官方安装运行 `<bin> update`，Grok 失败时回退官方安装脚本；Homebrew 运行 `brew upgrade [--cask] <name>`。
- 非交互 SSH 不加载 shell rc，脚本先以 `$SHELL -ilc` 读取登录 shell 的 PATH（有 `timeout` 时限制 15 秒；用 `env` 读取，兼容 fish），再补充 `~/.local/bin`、`~/.npm-global/bin`、`~/.grok/bin`、Volta、Bun、Homebrew 目录。
- 更新在远端限时 15 分钟，输出与退出码由脚本回传，失败时保留最后 12 行；`EACCES` 附带 sudo/用户级 Node 提示。同一主机同一 CLI 的并发更新被拒绝。
- 前端 `RemoteCliCard` 位于连接区与网关卡片之间，仅在连接成功后显示；当前应用排第一。已是最新只显示勾，有更新或拿不到最新版本时显示「更新」；「全部更新」逐个执行，失败不中断并刷新列表。更新当前应用后提示可直接「停止进程」。
- 远端 CLI 更新不读写远端配置文件，不影响切换、网关和 Codex 认证修复。
- 应用内 4.0.8 更新摘要第一条为远端 CLI 更新，替换官方「获取模型列表带请求头」一条，保持最多四条；四种语言均在长度限制内。
